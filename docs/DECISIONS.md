# DECISIONS (date | decision | reason)

| Date | Decision | Reason |
|---|---|---|
| 2026-11-22 | Docker init SQL (`/docker-entrypoint-initdb.d/`) creates `vector` extension and `life_ro` role only; `GRANT SELECT ON views TO life_ro` lives in the Alembic migration (`0001_init`), not in init SQL | Views don't exist until migrations run; granting in init SQL would silently fail. ARCHITECTURE §4b and DATA_AND_RAG §2 imply this split; making it explicit. |
| 2026-11-22 | `SearchHit.note_id` is the parent note FK (`note_chunks.note_id`), not the chunk PK | DATA_AND_RAG §5 lists note_date/source_type/snippet but not which ID; API_SPEC uses `note_id`; using the parent note FK is most useful to callers wanting to fetch the full note. |
| 2026-11-22 | PII masking applies to outbound payload only when model is not `ollama/*`; log-level redaction is always-on regardless of model | SECURITY §2 and AGENT_WORKFLOW Part B both say cloud-only payload masking; SECURITY §5 says always redact in logs. No conflict — two separate code paths. Noted for implementor clarity. |
| 2026-11-22 | Life-API uses TWO model roles: (1) GENERAL model (Ollama, LLM_MODEL in .env) for Text-to-SQL, result summaries, daily insights, query rewriting, structured JSON; (2) ROUTER model (Needle, optional, ROUTER_MODEL in .env) ONLY for the ReAct agent's tool selection step | Needle is NOT a replacement for the general model because it is a tool-calling model with little general chat ability; it never writes SQL or prose. |
| 2026-11-23 | Database port mapping changed to `127.0.0.1:5432:5432` in docker-compose.yml | Ensures PostgreSQL is only reachable locally from this machine for privacy. |
| 2026-11-23 | Python 3.12 venv used while ARCHITECTURE.md pins 3.11 | Existing environment runs Python 3.12.10 cleanly with all dependencies compatible. |
| 2026-11-23 | Minimal chunking and embeddings modules moved from Phase 4 to Phase 2 | The Phase 2 90-day synthetic seed script requires chunking and embeddings to populate `note_chunks` with real vector embeddings and `tsvector` columns. |
| 2026-11-23 | Note `content_hash` includes `note_date` and `source_type` (`f"{note_date}\|{source_type}\|{cleaned_content}"`) | Prevents false deduplication collisions across different dates and note sources when notes share similar or identical content structures, while preserving exact daily idempotency. |
| 2026-11-23 | Journal notes seed includes explicit sleep quality phrasing (`Slept badly...` for sleep < 6h) | Enables meaningful semantic and lexical hybrid search for natural queries like "slept badly" while maintaining 100% deterministic idempotency. |
| 2026-11-25 | Fixed `SEED_END_DATE=2026-11-23` default (overridable via env or `--end-date`) and `--reset` gated to `APP_ENV=dev`; removed `"Day N"` prefix and derived sleep prose strictly from `sleep_hours` | Prevents shifting date ranges across midnight runs from inserting duplicate journal rows or misaligning `content_hash`, and guarantees metric-consistent text and reproducible golden evaluations. |
| 2026-11-25 | Default `temperature=0.0` for `call_structured` and SQL summarization | Reduces sampling drift on structured JSON schemas, query rewriting, and Text-to-SQL generation with `llama3.1:8b`. |
| 2026-11-25 | Top-level SQL validator requires `exp.Select` root (`UNION` rejected; use `CASE WHEN` / `FILTER (WHERE ...)` / CTEs) | Strictly follows SECURITY.md §4 (`Root must be exp.Select`) and eliminates set-op smuggling vectors across allowlisted and non-allowlisted tables. |
| 2026-11-25 | Added optional `REFERENCE_DATE` (defaults to today in `APP_TIMEZONE`) and standardized `"last N days"` to mean `N` calendar days including the reference date (`date > ref - N AND date <= ref`) | Ensures evaluation prompts and expectations share one anchor when testing historical seed data, while keeping production default anchored to today. |
| 2026-11-25 | Results with 1 row & <=3 cols or `< 5` cells use a deterministic template summary; larger LLM summaries fail over to a value-listing template if any cited number is absent from returned rows | Eliminates confident numeric hallucinations on scalar/small results and enforces ground-truth numeric fidelity on multi-row summaries. |
